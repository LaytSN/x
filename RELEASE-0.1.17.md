# VK Play Cloud TV 0.1.17 — журнал ошибок и отчёты

Этот выпуск меняет диагностику, не настройки качества, декодирование или игровой ввод. Лаги и ошибки запуска ещё нужно поймать в отчёте; сам журнал их не исправляет.

## Что сохраняется

- Ошибки JavaScript и необработанные Promise, сообщения console.warn/error, сбои загрузки ресурсов и ограничения политики браузера.
- Этапы соединения, категории неуспешных сетевых запросов, состояние WebRTC, видеопотока, регистрации геймпада и переключения ввода. Метрики потока по-прежнему собираются раз в 2 секунды, не на каждом кадре.
- Номер запуска и отчёта, последние 120 событий и подробности ошибок. Повторяющиеся подряд сообщения сворачиваются в счётчик. Журнал прошлого запуска доступен после перезапуска.
- Не записываются тела запросов/ответов, содержимое WebSocket, чаты или нажатия с введённым текстом. Страницы VK ID исключены из нового журнала. Адреса, email и распознаваемые секреты удаляются из текста; произвольные объекты console не сериализуются. Перед передачей отчёта посторонним всё равно проверь его содержимое.

## Передача на Мак

Страница передаёт отчёт локальному сервису TizenBrew на самом ТВ. Сервис отправляет его приёмнику Мака `192.168.0.219:8787`. Это не внешний облачный сервер и не эмулятор Игрового центра.

Страница сохраняет до 3 последних неподтверждённых отчётов; сервис — до 12. При недоступности Мака сервис повторяет попытки с паузой 5–60 секунд. Очередь ограничена: это аварийный журнал, не бесконечный архив. При переполнении возможен явный отказ в приёме или замена старых записей. При запрете доступа к локальному сервису остаётся журнал в хранилище страницы. Очистка данных сайта удалит его; при недоступном хранилище остаётся только память до закрытия приложения.

| Статус | Значение |
| --- | --- |
| `sending` | Идёт сбор или передача |
| `queued` | Сервис сохранил отчёт на ТВ, но Мак ещё не подтвердил приём |
| `sent` | Мак подтвердил приём отчёта |
| `failed` | Отправка не подтверждена; причина и состояние хранения показаны отдельно |

Отчёт удаляется из очереди страницы только после подтверждения Мака. Сбой соединения или HTTP 200 без правильного подтверждения не считается доставкой. Зависшая статистика WebRTC ограничена по времени и не должна блокировать отправку.

При редком сочетании «Мак уже принял отчёт → диск ТВ перестал записывать → сервис перезапущен» возможна повторная доставка того же reportId. Сервис отмечает сбой сохранения подтверждения; это не гарантия единственного экземпляра файла на Маке.

## Кнопки пульта

- **Красная коротко:** собрать и отправить отчёт.
- **Красная удерживать около 2 секунд и отпустить:** открыть/закрыть журнал на ТВ, даже без Мака.
- В журнале **↑/↓** прокручивают записи, **Назад** закрывает его. Пока журнал открыт, игровой ввод приостановлен.
- **Жёлтая:** показать/скрыть общую диагностику, включая причину сбоя отправки и размер очереди. Постоянных плашек нет.
- Остальные кнопки, комбинации DualSense и профили 1080p/1440p остались как в 0.1.16.

## Проверка на телевизоре

После установки полностью выйди из старого модуля и запусти 0.1.17. Нажми красную, подожди до 25 секунд, открой жёлтую диагностику. Нужны строки «Отчёт», «Сервис», «Хранение», «Передача». Если `failed`, удержи красную и сфотографируй журнал.

На Маке проверена реальная цепочка HTTPS-страница → локальный сервис → HTTP-приёмник, а также отказ доступа к локальной сети, сохранение при сбое и восстановление очереди. Разрешение локального доступа и автозапуск сервиса именно на Tizen требуют этого теста на ТВ: локальные проверки не подтверждают их заранее.

Сервис слушает только `127.0.0.1:8788`, принимает точный Origin VK Play Cloud и ограничивает размер запроса. Публичного приёмника и отключения защиты браузера нет. Схема использует штатный [serviceFile TizenBrew](https://github.com/reisxd/TizenBrew/blob/main/docs/MODULES.md).
